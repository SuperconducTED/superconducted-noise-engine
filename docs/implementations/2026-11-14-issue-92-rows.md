## Implementation approach

**Scope first, clauses second.** A row is in Rule 7's scope when its value can change while no pull request touches
the repository: it reads `calibration-data`, an IBM service, or a workflow run. A row is out of scope when its value is
fixed by files in the merge graph (code, fixtures, committed evidence), by a released library version, or is a timing
of this repository's code on a named machine (those are superseded by desktop batch records, not by the data source).
Each in-scope row is then read in full for (a), (b) and (c). A regex pass found candidates; the classification below is
from reading each row.

**Anchors are measured, not inferred.** For a `calibration-data` row: the last commit at or before the measurement
instant (`git rev-list -1 --before=<t> origin/calibration-data`), then the row's own count at that commit, and the
range of commits over which the count holds. For a workflow-run row: the run's head commit is recorded, but it is not
a durable anchor when its branch is gone (`git ls-remote origin 'refs/heads/probe/*'` prints nothing; `a529bd56` and
`cf866fce` are in no fetched ref). The durable anchor is the `main` commit that carries the run's committed output, plus
the `calibration-data` commit for the archive side. Where the archive side is compared by blob id, equal blob ids at the
measurement ref and the tip prove the file content did not change, without reading it.

**Corrections are appended, never rewritten.** A re-sourced row keeps its original text; a dated clause is appended to
its Source and Notes. A retired row moves to the Retired table under the next `NC-R` id with "formerly NC-0xx" in its
reason, which is what happened to NC-013 when it became NC-R002 (`2f818961`).

**NC-009, no instant gives 11.1.** Let `s0` = 2026-05-13T12:13:22Z, the first snapshot's stamp. At the NC-011 anchor
the rate is `N / ((t - s0) / 1 d)` = 127 / 13.177 = 9.64 per day (40% of 24, not the 46% the 2026-05-25 documents

elapsed time measured from `s0`, the first file commit, or the branch root, finds no instant whose rate lies in
[11.05, 11.15). The same search for [9.60, 9.70) returns 905 hits, so the search can fire. One formula does give 11.1:

a count from one instant by a time span ending at another, about 40 hours earlier. That is a post-hoc fit, found by
searching, and is evidence of how the figure may have arisen, not a measurement at any ref.

**NC-031, recall against a moving denominator.** Let `S` be the stamps the 1 h sweep returned inside the window

## Design decisions

- **One question per situation, not per row.** Twenty-seven rows share one situation (pinned, clauses missing) and six
  share another (anchor found). Asking per row would be thirty-five questions with the same trade-off; the dialog takes
  four questions, and a different answer for one row goes in its "Other" field.
- **A dated line in place of a new rule interpretation.** The six rows' Source cells keep their original text, so a
  reader can see what the row said before 2026-11-14. Changing the value of an anchor in place is what Rule 7 forbids;
  appending the ref the value reproduces at is what #92 section 4 asks for ("which tree they were measured on").
- **No figure measured today goes into an old row.** NC-031's 43/50 at the tip is recorded here, not in NC-031's note:
  a current figure in an anchor row is exactly what clause (c) rules out. It gets a row only if a document needs it.
- **The script reads names, not contents.** Bengisu's clone is `blob:none`; a script that read snapshot contents would
  download hundreds of megabytes on first run. Blob-id equality proves "unchanged since the measurement" without that.
