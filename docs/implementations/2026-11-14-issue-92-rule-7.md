# 2026-11-14: issue-92-rule-7

Issue #92 (@bengisucvd) proposes Rule 7 for the numerical-claims register: a claim measured from outside this
repository's merge graph is a dated anchor at an immutable ref, names the live artifact that supersedes it, and is not
cited as the current value. The phase-4 plan (`docs/roadmap/2026-10-23-phase-4-plan.md`, lane 3) lists the ticket as
"adopt as written". This change adopts the rule. Applying it to the six rows the ticket found unpinned is a follow-up,
so this PR refers to #92 and does not close it.

## Problem / Motivation

Rule 6 protects rows measured by a command run against this repository: the PR that changes the command's output
updates the row. A row whose source is a data branch (`calibration-data`), an external service or a workflow run is
invalidated by that source, and no pull request ever touches it, so Rule 6 never fires. Rule 4's ninety days are far
slower than an hourly poller. Issue #92 measured the cost on NC-011: "127 snapshots, 2026-05-25" against 994 on the day
the ticket was written, with no `STALE` flag and no ref from which 127 could be reproduced.

Since the ticket was opened, fourteen rows have been written in the proposed form and cite it in their notes (NC-077 to
NC-086 and NC-088 to NC-091, as "the form Issue #92 proposes as Rule 7" or "the same Rule 7 form as NC-077"); NC-077
adds "that rule is still proposed". NC-047 followed the form before it was written down (#92 section 3). The register's
Rules section does not contain the rule, so those notes point at a rule that does not exist in the file.

## Implementation approach

The rule text is #92 section 3's English block, copied without edits, as rule 7 after rule 6. A short note under it
records the date it was added and the ticket, and says two things a reader would otherwise have to work out:

1. Rows written while the rule was proposed describe themselves in its form and are not edited. Rows are not rewritten
   to track this file's rules; that is the same reasoning as NC-R002's "dated docs are reconciled by appending".
2. The six rows #92 section 2 found without an immutable ref (NC-009, NC-011, NC-026, NC-029, NC-031, NC-034) do not
   meet the rule yet. They are anchored or retired under Rule 5 in a follow-up, not silently.

No row, value or date changes here, so Rule 6's NC-021 is not touched.

## Mathematical / Statistical details

N/A for the rule itself, which is structural.

One measurement was made for the follow-up and is recorded here so it is not lost. NC-011 says 127 snapshot files,
measured 2026-05-25. Counting `snapshots/*.json` in the tree of the last `calibration-data` commit before a given time:

```bash
c=$(git rev-list -1 --before="2026-05-25T23:59:59Z" origin/calibration-data)
git ls-tree -r --name-only "$c" | grep -c '^snapshots/.*\.json$'
```

gives 116 at 00:00Z, 118 at 12:00Z and 124 at 23:59Z on 2026-05-25 (commits `be07d8df`, `07f49ade`, `05ac491c`). The count
first reaches 127 at `6321e5f5` (committed 2026-05-26T16:28:34Z) and holds until `0ecf2aa4` (19:03:26Z). So 127 is
reproducible, at a ref one day after the row's stated date. That is what the follow-up starts from; whether the row is
re-sourced to `6321e5f5` with a dated note or retired under Rule 5 is the follow-up's decision, not this PR's. NC-009's
"about 11.1 snapshots per day" has not been reproduced by any formula tried, so it is the other row #92 singles out.

## Design decisions

- **Adopt as written.** The plan says so, and fourteen rows already cite the wording; editing the rule now would leave
  them describing a different text.
- **A note, not edits to the rows.** Rewriting the notes of the fourteen rows from "proposed" to "adopted" would change
  dated rows to track a later decision, which is what Rule 7 itself forbids for anchors.
- **The six rows in a follow-up.** Each needs its own anchor search, like NC-011's above, and a decision between
  re-sourcing and retiring. Mixing that into the rule's adoption would make one review carry seven decisions.
- **Refers to #92, does not close it.** The ticket's definition of done has five items; this PR does one.
