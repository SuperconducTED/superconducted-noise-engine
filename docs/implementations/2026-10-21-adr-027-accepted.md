## Design decisions

- **Posted comment, not the local draft, as the source of the register text.**
  The approved draft lives in an untracked file of another worktree. Copying from
  the comment makes the register match what readers of #84 saw. The entries were
  also checked byte for byte against the draft before posting (SHA-256 of the
  entry block, equal).
- **No "Outstanding items, as of 2026-10-21" table in the register.** The
  2026-10-03 section says each item "now closes through an entry below", so the
  four entries are the record. A second table would restate them.
- **The Advisor decision line is dated 2026-10-13, not 2026-10-21.** The line
  dates a decision, and the item 1 entry gives 2026-10-13 as the day it was given.
  The record date (2026-10-21) is named inside the line. The line names
  @mertefesensoy as approver under the delegation, so it cannot be read as
  "Dr. Akba decided on 2026-10-13".
- **The ADR-014 note cites rows, not numbers.** The close plan asked for no
  number in the note. The distinct-state count grows with the archive, and a
  number written into a dated note goes stale (the 2026-09-07 note's floor
  already has). NC-069 (2026-10-16, archive `d62f2cd`) is the registered count
  of the unit NC-012 counts at the latest archive ref, and its own Notes say the
  gate is not met. NC-025 (2026-08-30), the row the close plan named, predates
  it. PR #113 later added NC-070, a row dated 2026-10-17 that counts the same
  unit at `e5688d2` (2026-10-10), an ancestor of `d62f2cd`. The note therefore
  says "at the latest archive ref" rather than "latest registered count", so a
  row dated later is not mistaken for a later count.
- **Left as written:**
  - The draft `docs/decisions/drafts/ADR-027-calibration-training-target.md`
    still says Open. The ledger's preamble says drafts stay as the authoring
    record and the ledger is canonical.
  - Dated documents that quote ADR-027 as Open or proposed stay as they are:
    the phase-3 plan's M1 row, the 2026-09-09 cycle-2 close, the 2026-09-05
    verification record and the 2026-10-11 ANFIS M2 record. Dated docs are
    append-only.
  - The Consequences sentence "The proposal supplies one testable target"
    describes what the entry supplies, not its status.
  - The Consequences sentence about `HybridANFISTrainer` not landing under this
    ADR still holds. PR #114 landed the trainer core under Issue #60 and cited
    ADR-027 as evidence only. ADR-014 stays Deferred.
- **No new ADR or NC id.** This PR adds none, so no id can collide.
- **PR #79's alignment is pointed to, not judged.** The Pending paragraph
  describes #79 at `5400702`, the head the item 1 entry names. On 2026-10-21
  PR #79 added `6b39bcdf`, which aligns `build_reference`'s skip rules with
  ADR-027. Per qubit it uses `t1_missing`, `t2_missing`, `nonpositive` and
  `t2_exceeds_2t1`; it applies `gate_length_missing` per gate. On Mert's word
  (2026-10-23) a dated `> Revisited` note under ADR-027 says so. It names the
  head at the time of writing (`e15c0479`, which only merges `main` and leaves
  `reference.py` as at `a25140d`). Whether the alignment meets the obligation is
  left to Issue #58's review.
- **Merge order in the register.** PR #113 merged first (`88fa6a40`,
  2026-10-23). It had also appended a 2026-10-21 entry at the register's tail,
  which gave this branch a text conflict there. The conflict was resolved by
  merge order, as the register's 2026-09-29 reconciliation records: #113's entry
  stays first, and this PR's four entries follow it unchanged. #113's ADR-013
  note merged cleanly beside this PR's ADR-014 note. Open PR #79 also appends to
  the register's tail and leaves its section unnumbered until both have merged.
- **No closing keyword.** Mert closes #57 in step 6 with a comment that checks
  each §10 box against live state.
