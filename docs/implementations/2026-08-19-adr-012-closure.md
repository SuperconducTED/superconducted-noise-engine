# 2026-08-19: ADR-012 closure

## Problem / Motivation

ADR-012 already described the shipped squashing behavior, but stayed as Open.
This change records its decision without changing runtime behavior: the
noise-probability default must be explicit before the differentiable path
is used in the SGD trainer work for ADR-014. Closes issue #22.

## Implementation approach

This is a documentation-only change to the ledger. Only for noise-probability pipelines, when a pipeline is constructed, `ProbabilityClip` is the default. `IdentitySquashing` and `SigmoidSquashing` are still available to choose, with the latter still remaining the differentiable path for ADR-014.

## Mathematical / Statistical details

N/A — purely structural. This change records a decision in the ADR ledger
and introduces no formula, statistical test, or numeric algorithm. The
squashing functions themselves are unchanged; `ProbabilityClip` remains
elementwise `clip(x, 0, 1)` and `SigmoidSquashing` remains the numerically
stabilized logistic `1 / (1 + exp(-x))`.

## Design decisions

The ADR deliberately does not define a default selector at the module level. `FuzzyNoiseModel` and `FuzzyNoiseModelEnsemble` require a `SquashingStrategy`, which retains selection at the pipeline construction and avoids a change in behavior for other callers.

The alternative considered was a module-level default constant in
`squashing.py`. It was rejected as out of scope by issue #22 and because it
would silently change behavior for callers outside the noise-probability
path, which the ADR explicitly leaves free to choose.

The status table in `docs/state-of-the-project/2026-05-25-bootstrap-to-cycle-1.md`
is reconciled by appending an as-of-stamped section rather than editing the
2026-05-25 rows in place, per the dated-doc convention recorded in issue #25
and already practiced in `docs/roadmap/2026-05-25-cycle-2-plan.md`. Editing
the rows in place would destroy the point-in-time record the filename dates.
