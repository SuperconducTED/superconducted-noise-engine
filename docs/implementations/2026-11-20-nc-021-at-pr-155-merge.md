## Implementation approach

### The measurement

The row's own two commands were run from the exact-pin interpreter (Python 3.12.10, NumPy 2.4.4, Qiskit 2.4.1,
Aer 0.17.2, pytest 9.0.3, `PYTHONPATH=src`) in a throwaway tree at `C:/t155m`:

```bash
python -m pytest tests/ --collect-only -q -o addopts="" -p no:cacheprovider
python -m pytest tests/ -q -p no:cacheprovider
```

The throwaway tree held the trial merge of PR #155's head `353412d7` into `0971c143` (`main` at the time),
made with `git merge --no-commit`. The merge was clean, and its tree was `51c9265a`. The run went from 06:58:02
to 07:04:20 UTC, and PR #155 was merged at 07:04:53 UTC as `b9fcddea`. After the merge,
`git rev-parse b9fcddea^{tree}` printed `51c9265a070d770d2b4384403f910bf75530f0d3`, the same object. So the run
measured exactly the tree that the merge commit records, although the commit did not yet exist when the run
started.

Its skip message asks for the `calibration-data` ref to be fetched first. The laptop run could read that ref,
so the test ran there.

### The import path

The exact-pin interpreter has the package installed in editable mode, pointing at another local
worktree. So the run's imports had to be checked, not assumed. The run itself printed no
`superconducted.__file__`, and `C:/t155m` was removed after the merge. Three pieces of evidence settle it:

1. pytest's header reports `rootdir: C:\t155m`.
2. The same interpreter, given `PYTHONPATH=src` in a fresh tree of `b9fcddea` at `C:/t021`, imports the package
   from `C:\t021\src\superconducted\__init__.py`. Entries from `PYTHONPATH` come before the editable install,
   so the same rule held in `C:/t155m`.
3. The other worktree's `src/superconducted/integration/` has no `perturbation.py`, which PR #155's tests
   import. All 1432 tests passed, so the run cannot have imported from that worktree.

CI's 1431 passed and 1 skipped on `b9fcddea` is an independent check that the merged code passes.

### The merges between

Four of today's merges change no code. PRs #145 (`58f7f63c`), #147 (`655eb955`), #157 (`eda10288`) and #151
(`9e23af6d`) have the same `src` and `tests` trees and the same `pyproject.toml` as `667972c5`, so `1203`
holds at each of them by tree identity. That is not a run, and the row says so.

PR #140's merge `0971c143` changes `tests/`, and it was not measured on its own. The clause written on
2026-11-14 says each open PR that adds tests "re-measures at its own merge and does not derive". For #140 that
did not happen. The row now says so and records no laptop value for `0971c143`. CI's count there is cited as
CI's.

## Design decisions

- **A new record, not an appended section.** The 1203 entry was recorded on PR #145's branch with its section in
  `2026-11-09-phase-4-records-and-redate.md`. PR #145 is merged, and dated docs are append-only, so this change
  gets its own dated document.
- **One measurement after both merges.** #140 and #155 merged about 45 minutes apart. The full suite was run once, on
  the second merge's tree, because that was the one the merge decision needed. Measuring `0971c143` now is
  still possible (check it out and run the two commands); it is left as Mert's call rather than done unasked.
- **The command cell says "on the tree of".** Earlier entries say "both run at" a commit. Here the run came
  before the commit existed. The cell names the commit and its tree, and the Notes clause says how the two are
  known to be the same.
- **CI is cited, not adopted.** The row's value is the collected size. CI's 1431 passed and 1 skipped is
  written as CI's, beside the laptop's run, as on 2026-11-14.
- **The open-PR list counts PRs that touch `tests/`.** As of `b9fcddea` those are #142, #143, #150 and #158.
  Whether each one adds cases or only edits them is for its own merge to measure.
