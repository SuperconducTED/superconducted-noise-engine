## 0. Where cycle 2 landed, in one paragraph

The cycle-2 plan (`docs/roadmap/2026-05-25-cycle-2-plan.md`) bet that the critical path
ran through accumulating 630 snapshots by ~2026-07-10 (NC-R002, retired). It did not:
the counting unit was wrong (files, not device states) and the poller was losing what it
caught, which is what issues #45, #46, and PRs #50 and #55 spent late August
establishing. Measured against the six cycle-2 goals, one was met (PR #14 merged and
ADR-018 Accepted), three were missed (the 630 floor and trainer, ADR-014; the
membership-function ablation, ADR-019; T1 vs IT2, ADR-009) and two were deferred
(ADR-015, ADR-016). What the plan had no row for is most of what got done: six ADRs
reached Accepted (006, 010, 012, 018, 023, 025), the ledger became a canonical audited
instrument with a numerical-claims register behind it, and the whole data-integrity
programme (#45, #46, #50, #52, #53, #54, #55) was not in the plan at all. Cycle 2 was
a governance and correctness cycle; the cycle-2 close record
(`docs/state-of-the-project/`, ticket #56) carries the full scorecard.

## 1. The finding that reframes phase 3

ADR-019's own gate note (2026-08-20) says prerequisite (a), the tanh shapes from PR #14,
is cleared, and prerequisite (b) is "neither the ADR-014 trainer nor a manual
parameterization has yet produced non-trivial MF parameters." The ablation is therefore
blocked on somebody producing manual membership-function parameters, a self-contained
task with no data dependency, and ADR-009, the highest-fan-out decision in the ledger
(it gates ADR-011, ADR-015, and ADR-021), is waiting on that ablation. Nothing in that
chain waits on the snapshot floor.

The second reframing is the trainer itself. Both shipped defuzzifiers are linear in the
consequent parameters (`fuzzy/defuzzification.py`; see the T-BURAK-1 design), so one
least-squares stage serves the Type-1 and the Interval Type-2 paths, and the premise
update is a gradient step through whichever firing bounds exist. The trainer can be
built now, type-agnostically, and ADR-009 only fixes the final configuration and the
parameter count. That is the move that puts "results from ANFIS" inside September.

The third came out of planning this phase and is a defect, filed as #66.
`BasicCalibrationVectorizer.extract` reads per-qubit values without the unit scaling
`loader.py` applies to the same fields, so it returns microseconds where the rest of the
repo assumes seconds. On a real archived snapshot the ratified 3x3x3 grid fires at
exactly zero on both coherence dimensions and the bootstrap pipeline raises
`ZeroDivisionError` from `WeightedAverageDefuzzifier`. Measured 2026-09-03 against
`snapshots/2026-08/ibm_fez/20260831T203902000000Z.json`: the loader path returns
`1.214277e-04` s and the vectorizer `1.214277e+02`, exactly 1e6 apart. Every existing
test of `extract` writes its own values in seconds and asserts seconds back, and the
smoke script's synthetic snapshot does the same, which is why three cycles of work never
hit it. The consequence for phase 3 is that no membership-function grid may be derived
from `FEATURE_SCALES`; every grid comes from the archive's measured quantiles, in the
units the code actually produces, stated explicitly.

## 3. The architectural moves

1. **Type-agnostic trainer.** Weighted-average and Nie-Tan outputs are both
   `sum_r w_eff_r * (A_r [x; 1])` with `w_eff_r = wbar_r` (T1) or
   `0.5 * (wbar_low_r + wbar_high_r)` (IT2). One design matrix, one solver.
2. **Physics-anchored target in raw parameter space.** Per qubit, the backend's own
   `T1`, `T2`, and reference gate length `t` determine the amplitude and phase damping
   rates a crisp calibration twin would use: `gamma = 1 - exp(-t / T1)` and
   `lambda = 1 - exp(-t * (2 / T2 - 1 / T1))`, the pair for which the composed
   amplitude+phase damping channel in `channels/kraus.py` equals Qiskit Aer's
   `thermal_relaxation_error(T1, T2, t)` at zero excited-state population (checked
   2026-09-02 by SuperOp comparison to machine precision for T2 below, equal to, and
   above T1; the ADR re-derives and pins this with a test). The snapshot-level target is
   the mean over usable qubits with the per-qubit spread retained for ADR-015 / ADR-016.
3. **Data-driven manual parameterization with anchored consequents.** Premises from a
   quantile grid partition of the archive's feature distribution, for all seven shapes;
   zero-order consequents anchored at the physics target at each rule's centre. No
   random draw, so ADR-024's one-in-four identity-channel trap does not apply, and the
   ablation measures shape interpolation rather than a consequent draw.
4. **A `training` package, no LOCKED edits.** `targets.py`, `dataset.py`, `anfis.py`,
   `gradients.py`; the trainer rebuilds `TSKRule` objects rather than mutating
   `fuzzy/tsk.py`'s read-only consequents.
5. **Instruments before measurements.** The harness cannot run the ADR-019 protocol as
   shipped: `StateFidelity` needs density matrices while the harness produces counts, and
   `run_benchmark` converts that failure into a silent `NaN`; `simulate_reference` on the
   QFT circuit raises `unknown instruction: qft` because nothing transpiles before
   `AerSimulator.run` (measured 2026-09-03 in the scratch environment on qiskit 2.4.1
   and qiskit-aer 0.17.2; the SU2 ansatz, GHZ, and Clifford circuits run, so ADR-021's
   "QFT, efficient_su2" consequence is half stale). Worse, `FuzzyNoiseModel.prepare`
   registers errors on the instruction names of the circuit it is given, so preparing an
   untranspiled QFT circuit yields an empty noise model, and transpiling afterwards
   against a plain `AerSimulator` keeps `h`, `x`, `cp` and `swap` in Aer's native basis
   so an error registered on `sx` never fires. The harness must transpile to the noise
   model's basis first and prepare second. Those are fixed and certified first.
6. **The instrument must resolve what the target predicts.** On `ibm_fez` the `sx` gate
   is 24 ns (read from `properties.gates` in the 2026-08-31T20:39:02Z snapshot), so
   the relaxation damping per gate is of order 1e-4 while the shot-noise floor of a
   4096-shot counts comparison is about 0.016. The ADR-019 protocol as written would
   rank shapes on noise. The certification ticket therefore measures the smallest
   parameter difference each mode resolves; the ablation runs in density-matrix mode
   (exact) as well as counts mode, and ranks on whichever can resolve the effect, saying
   so. The reference noise model is built in two scopes, single-qubit relaxation only
   (like-for-like with what the engine emits today: two-qubit gates and readout carry no
   noise, `integration/aer_factory.py` swallows the projector's `NotImplementedError`)
   and full device (showing the gap the ADR-008 follow-up must close).
7. **The data track runs in parallel.** Dashboard (#48), dated backfill (#53), sweep
   (#49, priority raised per #54), then the training-set builder.
8. **The floor is derived at M3 and the growth is projected from measurements only.**

## 6. The dataset, honestly

NC-025 records 504 distinct device states at `f0930b9` (894 files, 2026-08-28) against
the NC-012 floor of 630 distinct states, and NC-012 itself is a rule-of-thumb threshold
on a parameter count nothing derives (the "126" first appears verbatim in the
2026-05-07 bootstrap commit of `docs/architecture.md`, before the 27-rule grid existed;
on today's 3x3x3 Gaussian grid with two outputs the count is 234, and 126 is
reproducible only as one output's consequents plus the premises). The `calibration-data`
branch holds 921 snapshot files at `43dec77` (2026-09-02, GitHub tree API); a local
`git ls-tree` at `40a1ff4`, one poll behind, holds 920 -- reconcile the count against
the ref you actually index rather than repeating either figure. Its distinct-state count
