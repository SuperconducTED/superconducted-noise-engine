# Cycle 2 Plan

## Cycle 2 Goals

- **Reach the 630-snapshot training floor and implement the TSK trainer** (ADR-014) · estimated ~2026-07-10 at sustained polling cadence (~11.1 snapshots per day). This is the critical-path bottleneck for all downstream empirical work.
- **Merge PR #14 and formalize ADR-018** · lands `TanhSigmoidMF` and `TanhBellMF`, unblocking the MF ablation protocol (ADR-019).
- **Execute the MF shape ablation** (ADR-019) · compare Gaussian, triangular, trapezoidal, and tanh-based shapes across four benchmark circuits using the defined protocol (4096 shots, ensemble size 8, Gaussian baseline).
- **Resolve T1 vs IT2** (ADR-009) · informed by ablation results and trainer feasibility. This has the highest fan-out in the dependency graph · it gates ADR-011, ADR-015, and ADR-021.
- **Implement per-member perturbation** (ADR-015) · deliver a non-degenerate ensemble where members produce distinct noise models, enabling meaningful benchmark aggregation and uncertainty quantification.
- **Close the mean-vs-sum aggregation ambiguity** (ADR-016) · align harness code, smoke script, and documentation to a single aggregation contract.

## Sequencing Recommendation

### Phase 0 · Immediate (now through 2026-06-01)

Clear zero-dependency decisions to avoid adding decision latency on top of data-collection latency.

1. **ADR-018** · Formalize the tanh slope positivity convention and merge PR #14. This is the sole gate on ADR-019 ablation via the manual-parameterization path. Pure convention · no data dependency.
2. **ADR-006** · Close the bootstrap MF shapes decision. This is the sole gate on ADR-009 (T1 vs IT2), which has the highest fan-out in the graph · it gates ADR-011, ADR-015, and ADR-021. No data dependency. Delaying this decision adds decision latency on top of the snapshot-floor wait.
3. **ADR-010** · Confirm the 3×3×3 rule grid baseline. No upstream gate · closes the gate on ADR-013 (vectorizer comparison).
4. **ADR-012** · Confirm ProbabilityClip as the default squashing strategy. No upstream gate · unblocks the trainer integration contract.

### Phase 1 · Early June (~2026-06-01 to 2026-06-08)

Type-system decisions and early empirical work.

5. **ADR-009** · Decide T1 vs IT2. With ADR-006 resolved, the type-system choice can be made. Unblocks ADR-011 (defuzzification), ADR-015 (perturbation), and ADR-021 (variance injection).
6. **ADR-011** · Finalize defuzzification method selection (weighted-average for T1, Nie-Tan for IT2). Follows directly from ADR-009.
7. **ADR-007** · Run empirical fuzzification placement comparison. Can proceed in parallel · requires only test infrastructure, not the snapshot floor.
8. **ADR-019** · Begin MF ablation with manual parameterization (PR #14 shapes now available). Does not require the trainer if manual parameters suffice for the comparison protocol.

### Phase 2 · Snapshot Floor (~2026-07-10)

Data-gated work unblocks.

9. **ADR-014** · Implement the TSK trainer. 630 snapshots accumulated · the target-distribution definition must be written before this date. This is the critical-path bottleneck.
10. **ADR-013** · Begin vectorizer comparison (also requires 630+ snapshots and ADR-010). Can run in parallel with ADR-014.

### Phase 3 · Mid-July (~2026-07-17)

Perturbation and ensemble.

11. **ADR-015** · Select the perturbation mechanism from the three candidates (input-vector noise, premise-MF perturbation, IT2 footprint sampling). Both gates (ADR-009 and ADR-014) are now resolved.
12. **ADR-021** · Resolve the variance-injection open question. Follows directly from ADR-015 mechanism selection.

### Phase 4 · Late July (~2026-07-24)

Aggregation.

13. **ADR-016** · Finalize benchmark aggregation semantics (mean to interval upgrade). The perturbation mechanism from ADR-015 defines the distribution · aggregation semantics depend on it.

ADR-008 remains event-driven · it unblocks only if a channel is observed to violate CPTP-by-construction. No sequencing slot assigned · monitor passively.

**Critical path**: ADR-006 → ADR-009 → ADR-015 (also waiting on ADR-014 and the snapshot floor) → ADR-016. The binding constraint on the entire graph is the 630-snapshot floor at ~2026-07-10. All decision-only ADRs (ADR-006, ADR-010, ADR-012, ADR-018) should be closed immediately to avoid compounding decision latency with data-collection latency.
